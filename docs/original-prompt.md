# Промпт: «Sightline» — зовнішній оверлей прицілу + монітор продуктивності для Windows

> Скопіюй усе нижче (від розділу «0. Роль») в агента-розробника (Claude Code чи інший).
> Назва «Sightline» робоча, її можна змінити.

---

## 0. Роль і мета

Ти senior-розробник під Windows (C++20, Win32, DirectX/DirectComposition, ETW). Потрібно спроєктувати й реалізувати десктопну програму для Windows 10 22H2+ / Windows 11, яка:

1. Малює **власний приціл поверх гри** у режимі *borderless / windowed fullscreen*.
2. Показує **оверлей продуктивності**: FPS, frametime, 1%/0.1% low, графіки, CPU/GPU/RAM/VRAM, температури, частоти, енергоспоживання. Усе налаштовується, є гарячі клавіші.
3. **Не втручається в процес гри.** Через це її не повинні блокувати чи банити античіти (EAC, BattlEye, Vanguard, Ricochet, VAC, FACEIT, EA Javelin).
4. **Майже не впливає на продуктивність.** Статичний приціл споживає ~0% CPU/GPU, а оверлей не додає затримки виводу кадру.

Спілкуйся зі мною українською, але **всі коментарі в коді пиши тільки англійською**. Коментарі суто технічні: що робить код, чому ухвалено неочевидне рішення, обмеження, крайні випадки. Без розмовних ремарок.

### 1.2. Болі гравців, які треба закрити (з форумів Steam/EA/Blur Busters/GitHub)

1. **«Чи мене забанять?»** Відповідь завжди розмита. → Робимо прозору архітектуру без ін'єкції та прямо в UI пояснюємо, що програма робить і чого не робить.
2. **Приціл зникає після Alt+Tab** або коли гра піднімає своє вікно поверх. → Подієве відновлення topmost (див. 4.3).
3. **Падіння FPS / додаткова затримка через оверлей.** Прозоре вікно поверх borderless-гри може вибити її з *Independent Flip* у *Composed Flip* (+1 кадр затримки, ламається VRR/G-Sync). → Головна технічна вимога (див. 4.2) плюс вбудована діагностика.
4. **Приховування при прицілюванні (ADS)** з режимами hold/toggle, як у налаштуваннях гри.
5. **Профілі для кожної гри**: свій приціл, позиція, колір і набір метрик автоматично за exe активного вікна.
6. **Неточний центр**: зсув на 1 px через парну/непарну роздільну здатність, DPI-масштабування або windowed-вікно не по центру екрана.
7. **FPS-оверлей, який не ламається під античітом**, на відміну від RTSS.
8. **Різні формули 1% low** в різних програмах. → Показуємо, яким методом рахуємо, і даємо вибір.
9. **Реклама, телеметрія, «важкі» Electron-клієнти.** → Жодної реклами, телеметрія тільки opt-in, нативний код.
10. **Перенесення прицілу з улюбленої гри.** → Імпорт кодів прицілу Valorant і CS2.

## 2. Жорсткі обмеження «anti-cheat friendly»

Мета не в тому, щоб *сховатися* від античіта, а в тому, щоб **нічого не робити з процесом гри**. Ніякого маскування чи обходу детекту. Прозорість і є стратегією.

**ЗАБОРОНЕНО (не реалізовувати навіть як опцію):**
- DLL-ін'єкцію, `CreateRemoteThread`, `SetWindowsHookEx` з глобальними DLL-хуками, хуки DXGI/D3D/OpenGL/Vulkan, Vulkan-layers, підміну `Present`.
- `OpenProcess` на процес гри з правами крім `PROCESS_QUERY_LIMITED_INFORMATION` (потрібні тільки ім'я exe і PID для профілів). Ніякого `ReadProcessMemory`/`WriteProcessMemory`.
- Будь-який аналіз пікселів екрана гри в реальному часі (Desktop Duplication, `BitBlt` області під прицілом, «адаптивний колір під фоном»). Патерн «читаю пікселі біля центру» = поведінка triggerbot.
- Відправку вводу (`SendInput`, `keybd_event`, `mouse_event`), макроси, компенсацію віддачі, будь-які «aim assist»-функції, зміну позиції прицілу залежно від стрільби в грі.
- Власні kernel-драйвери і драйвер **WinRing0** (Defender: `VulnerableDriver:WinNT/Winring0`, CVE-2020-14979).
- Пакувальники/обфускатори exe (UPX, Themida тощо), рандомізацію імені процесу чи вікна, приховування процесу. Exe має стабільне ім'я, стабільний клас вікна та цифровий підпис.
- Зміну файлів гри та її конфігів.

**ДОЗВОЛЕНО (тільки публічні API ОС, без доступу до гри):**
- Окреме вікно процесу програми: topmost, прозоре для кліків.
- `SetWinEventHook(... WINEVENT_OUTOFCONTEXT)`: out-of-context, без ін'єкції. Тільки для подій foreground/location.
- `RegisterHotKey` для звичайних комбінацій; **Raw Input** (`RegisterRawInputDevices` з `RIDEV_INPUTSINK`) для пасивного читання стану кнопок миші/клавіш (ADS/hold). Без LL-хуків (`WH_KEYBOARD_LL`/`WH_MOUSE_LL`), бо деякі античіти їх моніторять. Якщо Raw Input не покриває кейс, LL-хук дозволений тільки як опція, вимкнена за замовчуванням, з попередженням.
- ETW-провайдери `Microsoft-Windows-DXGI`, `Microsoft-Windows-DxgKrnl`, `Microsoft-Windows-Win32k` для frametime (так працює PresentMon).
- Вендорні SDK телеметрії: NVML (NVIDIA), ADLX (AMD), IGCL (Intel), PDH-лічильники, DXGI `QueryVideoMemoryInfo`, D3DKMT-статистика.

**У UI обов'язково:**
- Сторінка «Безпека», де простими словами описано, що програма робить і чого не робить, плюс чесне застереження: *«Жоден сторонній оверлей не має офіційної гарантії від розробників ігор. Деякі турнірні платформи та ліги прямо забороняють сторонні приціли. Перевір правила гри.»*
- **Список «Competitive-safe»**: exe, у яких оверлей автоматично вимикається (користувач редагує список; за замовчуванням порожній, плюс підказка додати турнірні клієнти).
- Режим «Сон до запиту» (як у HudSight): після старту приціл прихований, доки користувач не натисне хоткей або не запуститься гра з білого списку.

## 3. Бюджети продуктивності (критерії приймання)

| Стан | CPU (сумарно, 8-ядерний CPU) | GPU | RAM (private) | Пробудження потоків |
|---|---|---|---|---|
| Статичний приціл, оверлей метрик вимкнено | ≤ 0.05% в середньому | ~0 (кадр рендериться тільки при зміні) | ≤ 25 MB | 0 періодичних таймерів |
| Анімований приціл (30 fps cap) | ≤ 0.3% | ≤ 0.2% | ≤ 30 MB | тільки під час анімації |
| Оверлей метрик, текст 2 Гц, графік 20 Гц | ≤ 0.5% | ≤ 0.3% | ≤ 45 MB | ≤ 25/с |
| Вікно налаштувань відкрите | без обмежень | без обмежень | процес UI закривається повністю, коли вікно закрите | — |

**Головне:** оверлей **не повинен переводити гру з Independent Flip у Composed Flip** там, де залізо підтримує MPO (Multiplane Overlay). Перевірка: PresentMon CLI показує `Hardware: Independent Flip` або `Hardware Composed: Independent Flip` з увімкненим оверлеєм. Якщо це неможливо на конкретному залізі, програма **сама це виявляє і показує попередження** (див. 6.4).

Правила, щоб вкластися в бюджети:
- Повністю подієва модель: `MsgWaitForMultipleObjectsEx`, без busy-loop і без `Sleep`-циклів. Коли нічого не змінюється, потік спить.
- Статичний приціл: рендер один раз, потім `Present` тільки при зміні налаштувань/DPI/монітора.
- Анімації: окремий waitable timer з обмеженням fps (за замовчуванням 30, налаштовується 15–144), таймер працює **тільки** поки анімація активна.
- Телеметрія: опитування сенсорів за замовчуванням раз на 1 с (налаштовується 0.25–5 с); ETW-подiї агрегуються в кільцевому буфері без алокацій на кожен кадр.
- Потоки телеметрії: `SetThreadInformation(ThreadPowerThrottling)` (EcoQoS) і нижчий пріоритет. Процес оверлею **ніколи** не підвищує свій пріоритет вище Normal.
- Ніяких алокацій у гарячому шляху рендера; кешувати геометрію Direct2D і текстові layout'и DirectWrite, перебудовувати тільки при зміні рядка.
- Мінімальна площа поверхонь: поверхня прицілу дорівнює bounding box прицілу (наприклад 64×64), **а не весь екран**. Панель метрик дорівнює своєму прямокутнику. Мала площа — менше роботи DWM і вищий шанс отримати апаратну MPO-площину.

## 4. Архітектура

### 4.1. Стек і процеси

- **Мова:** C++20, MSVC, CMake + vcpkg. Без .NET/Electron/WebView у процесі оверлею.
- **Процеси:**
  1. `sightline.exe` (**Core**, без підвищення прав): оверлей прицілу, панель метрик, хоткеї, профілі, трей. Ціль ≤ 25–45 MB.
  2. `sightline-telemetry.exe` (**Telemetry helper**): ETW-сесія для frametime, сенсори GPU/CPU. Для ETW-провайдерів DxgKrnl потрібен адміністратор **або** членство користувача в групі *Performance Log Users*. Запускається на вимогу (тільки коли оверлей метрик увімкнено). Є два варіанти, обидва з явною згодою користувача: (а) одноразовий UAC-запуск; (б) кнопка «Додати мене в Performance Log Users» з поясненням. Можна взяти бібліотеку `PresentData` з репозиторію GameTechDev/PresentMon (MIT); вказати ліцензію в THIRD-PARTY-NOTICES.
  3. `sightline-settings.exe` (**Settings UI**): окреме вікно. Варіант за замовчуванням: Dear ImGui (docking branch) на D3D11 у звичайному вікні. Процес **завершується**, коли вікно закрите, тому в грі він нічого не їсть.
- **IPC:** спільна пам'ять (`CreateFileMapping`) з seqlock для метрик Telemetry→Core; іменовані події для сповіщень; named pipe з JSON-повідомленнями для команд Settings→Core (застосувати конфіг, live preview). Імена об'єктів з префіксом `Local\Sightline.*`.
- **Конфіг:** `%APPDATA%\Sightline\` → `config.json` (версійна схема, міграції), `crosshairs\*.json`, `hud-layouts\*.json`, `profiles.json`. Атомарний запис через тимчасовий файл і `ReplaceFile`. Будь-яка помилка парсингу означає відкат на останню валідну копію `.bak`.

### 4.2. Вікно оверлею (критично для FPS і затримки)

- Стилі: `WS_EX_NOREDIRECTIONBITMAP | WS_EX_TOPMOST | WS_EX_TOOLWINDOW | WS_EX_NOACTIVATE | WS_EX_TRANSPARENT | WS_EX_LAYERED` (layered з `SetLayeredWindowAttributes(alpha=255)` тільки щоб гарантувати click-through між процесами; перевір на цільових збірках Windows, що це не ламає DirectComposition-шлях. Якщо ламає, використовуй `WM_NCHITTEST → HTTRANSPARENT` разом з `WS_EX_TRANSPARENT`).
- Рендер: **DirectComposition** + `IDXGISwapChain1` через `CreateSwapChainForComposition`, `DXGI_SWAP_EFFECT_FLIP_SEQUENTIAL`, `DXGI_ALPHA_MODE_PREMULTIPLIED`, `DXGI_FORMAT_B8G8R8A8_UNORM`, 2 буфери; малювання через Direct2D 1.1 / DirectWrite на D3D11-пристрої (`D3D11_CREATE_DEVICE_BGRA_SUPPORT`). Без `UpdateLayeredWindow` з повноекранним GDI-бітмапом (дорого і гарантовано composed).
- Окремі DComp-візуали для прицілу і для HUD, кожен свого розміру; їх можна рознести в два окремі вікна, якщо це дає кращий результат за MPO (виміряти обидва варіанти і залишити кращий).
- `Present(1, 0)` тільки при зміні вмісту; кадр анімації через `Present(0, 0)` з таймером.
- `DwmSetWindowAttribute(DWMWA_EXCLUDED_FROM_PEEK)`, вимкнути тіні/анімації DWM для вікна.
- Per-Monitor-V2 DPI awareness (маніфест). Розміри прицілу задаються **у фізичних пікселях**, щоб масштабування Windows 125%/150% не розмивало лінії.
- `SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE)` тільки як опція користувача «Не показувати приціл на стрімі/запису» (за замовчуванням вимкнено).
- **Падіння D3D-пристрою** (`DXGI_ERROR_DEVICE_REMOVED`, зміна драйвера, підключення монітора) → повне перестворення пристрою без перезапуску процесу.

### 4.3. Утримання поверх гри і позиціювання

- `SetWinEventHook(EVENT_SYSTEM_FOREGROUND, …, WINEVENT_OUTOFCONTEXT)` і `EVENT_OBJECT_LOCATIONCHANGE` (фільтр по hwnd активного вікна). При зміні foreground: визначити exe через `QueryFullProcessImageNameW` (PID з `GetWindowThreadProcessId`, handle тільки `PROCESS_QUERY_LIMITED_INFORMATION`), застосувати профіль, повторно підняти topmost (`SetWindowPos(HWND_TOPMOST, … SWP_NOACTIVATE|SWP_NOMOVE|SWP_NOSIZE)`).
- **Без періодичного таймера «re-topmost»**, тільки події. Як запобіжник допускається одна перевірка через 500 мс після зміни foreground.
- Центр прицілу: за замовчуванням центр **клієнтської області** активного вікна гри (`GetClientRect` + `ClientToScreen`). Альтернатива: центр монітора. Ручний зсув X/Y. Режим «зсув стрілками, поки затиснуто хоткей» з рамкою-підказкою.
- Піксельна точність: для непарної/парної ширини лінії автоматично вирівнювати на піксельну сітку; опція «зсув на пів пікселя», як у HudSight.
- Кілька моніторів: приціл на моніторі, де гра; переїзд при переміщенні вікна; запам'ятовувати монітор для профілю.
- Приховувати приціл, коли: активне не ігрове вікно (за фільтром процесів), відкрите вікно налаштувань Sightline, гра згорнута, активний робочий стіл блокування/UAC (`WTSRegisterSessionNotification`).
- **Exclusive fullscreen** у v1 не підтримується (зовнішнє вікно туди фізично не потрапляє без ін'єкції). UI це чесно пояснює і пропонує перемкнути гру в borderless. У v2 можна додати опційний віджет Xbox Game Bar (як у Crosshair X): окремий UWP-пакет, офіційний механізм Microsoft, без ін'єкції.
- (Опційно, v1.1) **UIAccess-режим**: підписаний exe, встановлений у `Program Files`, з `uiAccess="true"` у маніфесті, отримує z-band вище звичайних topmost-вікон. Це офіційний механізм доступності Windows; він допомагає в іграх, які самі ставлять topmost. Потрібні підпис коду та інсталятор.

### 4.4. Ввід і хоткеї

- Редактор хоткеїв: до 3 клавіш, включно з кнопками миші (M4/M5), режими *press / hold / toggle / hold-to-hide (inverse)*.
- Виявлення конфліктів між хоткеями (як у HudSight: «ця комбінація вже використовується…»).
- Ліва/права кнопка миші **без модифікатора** заборонені як хоткей перемикання (інакше він спрацьовує на кожен постріл); дозволені тільки як тригер ADS/Fire.
- Якщо гра запущена від адміністратора, а Sightline ні, Raw Input від неї не приходить (UIPI). Виявити це і запропонувати запустити Core від адміністратора.

## 5. Функції прицілу

### 5.1. Модель даних (шари, як у HudSight, але свій формат)
`Crosshair { id, name, category, tags[], fav, layers[], hotkeys, version }`
`Layer { type: vector|pixel|image, shape, size, thickness, gap, rays, rotation, roundness, arcStart, arcEnd, segGap, chevronAngle, fill{rgba, opacity, blur}, outline{rgba, opacity, thickness, blur}, offsetX, offsetY, scale, hidden, locked, animation? }`

Не копіювати файли пресетів, шрифти чи графіку HudSight/Crosshair X. Тільки ідея формату.

### 5.2. Форми
Хрест (з центральною крапкою і без), крапка, коло/кільце, T-подібний, квадрат, дужки `[ ]`, шеврони (in/out), стрілки (in/out), дуги, сегментоване коло, сектор, піксель-арт (редактор 1:1), імпорт PNG/SVG (SVG растеризується один раз при імпорті).

### 5.3. Параметри (кожен з повзунком і точним числовим полем)
Розмір/довжина, товщина, проміжок (gap), кількість променів, поворот, заокруглення кінців, **прозорість** (заливка і обводка окремо), **колір** (HEX/RGB/HSV, піпетка по скріншоту, який користувач сам завантажив, а не по живому екрану), обводка (товщина, колір, прозорість), м'яке розмиття/світіння, масштаб усього прицілу, глобальна «маска кольору» (як у HudSight) для швидкого перефарбування будь-якого пресету.

### 5.4. Палітри
- Висококонтрастні: неон-зелений `#00FF00`, ціан `#00FFFF`, маджента `#FF00FF`, жовтий `#FFFF00`, червоний `#FF0000`, білий з чорною обводкою.
- Режими для дальтоніків (протанопія/дейтеранопія/тританопія): набори кольорів, які гарантовано контрастні.
- «Останні кольори» і «Збережені кольори».

### 5.5. Готові пресети (≥ 40, згруповані)
- **Classic:** Simple Cross, Cross+Dot, Thin Cross 1px, Open Cross (великий gap), T-Shape.
- **Dot:** Micro Dot 2px, Dot 4px, Dot + Outline, Ring Dot.
- **Circle:** Ring, Ring + Dot, Segmented Ring, Shotgun Spread (велике коло).
- **Tactical:** Brackets, Chevron, Arrows, Mil-dot (тільки центр, без дальномірних міток).
- **Sniper/Scope-assist:** тонкий довгий хрест.
- **Accessibility:** великі контрастні варіанти для слабкого зору.
- **Fun:** анімовані/кольорові.
Пресети генеруються кодом із параметрів (нуль ассетів), зберігаються як JSON.

### 5.6. Сценарії використання
- **Hide on ADS**: прив'язка до ПКМ або іншої кнопки; режими hold/toggle; дії «сховати / показати тільки при ADS / переключити на інший приціл»; «вийти з ADS після пострілу» (для ігор, які самі виходять зі скоупу); скидання стану після Alt+Tab.
- **Перемикання прицілів**: хоткей на конкретний приціл, «поки затиснуто», циклічний набір.
- **Профілі для ігор**: автоматично за exe; кожен профіль = приціл + позиція + монітор + набір HUD + фільтр.
- **Анімації (опційно, v1.1)**: keyframes для параметрів, тригери Fire/Aim/Autoplay, криві easing. Тільки косметика від власного вводу користувача, без зв'язку з подіями гри.
- **Обмін**: експорт/імпорт JSON, **share-код** (base64url стиснутого JSON, без сервера), копіювання в буфер, імпорт перетягуванням файлу.
- **Імпорт з ігор**: парсинг коду прицілу Valorant (формат `0;P;c;…`) і share-коду CS2 (`CSGO-xxxxx-…`) у шари Sightline з максимальною відповідністю (колір, товщина, довжина, gap, обводка, центральна крапка). Покрити unit-тестами на відомих кодах.
- **Live preview**: у налаштуваннях фон-сітка / прозорий / скріншот гри, який завантажив користувач; превʼю 100% і зум до 800%.

## 6. Оверлей продуктивності

### 6.1. Метрики (обов'язкові)
**Кадри (з ETW, тільки для foreground-процесу або вибраного PID):**
- FPS (поточний, середній за вікно N с), **frametime (ms)**, **1% low і 0.1% low** з вибором методу: *(a)* середнє найповільніших 1%/0.1% кадрів (за замовчуванням) або *(b)* percentile 99/99.9 frametime. Метод показується в tooltip.
- Мін/макс FPS за сесію, кількість статерів (кадр > 2× медіани), стандартне відхилення frametime.
- **Present mode** (`Hardware: Independent Flip` / `Composed: Flip` / `Hardware Composed…`) — показник, якого немає в більшості оверлеїв і який допомагає знайти зайву затримку.
- Опційно (якщо доступно через PresentMon-метрики): GPU Busy, CPU Busy, display latency, частота оновлення монітора / стан VRR.

**Залізо:**
- **GPU:** завантаження %, температура (core/hotspot/memory, якщо є), частота ядра/пам'яті, енергоспоживання (W), VRAM використано/всього, обороти вентилятора. Джерела: NVML → ADLX → IGCL → fallback PDH `GPU Engine` + DXGI `QueryVideoMemoryInfo`.
- **CPU:** загальне завантаження, **максимальне завантаження одного ядра** (важливо для CPU-bound ігор), ефективна частота (PDH `Processor Information\% Processor Performance` × базова частота), температура (див. нижче).
- **RAM:** використано/всього, використано процесом гри (working set через `PROCESS_QUERY_LIMITED_INFORMATION`).
- **Інше:** годинник, тривалість сесії, батарея/живлення (ноутбуки), опційно ping до заданого користувачем хоста (ICMP, раз на 1–2 с; чесно підписати, що це **не** ping ігрового сервера).

**Температура CPU без власного драйвера:** джерела в порядку пріоритету: (1) shared memory **HWiNFO** (якщо користувач його запустив і ввімкнув SHM); (2) LibreHardwareMonitor через бекенд **PawnIO** (якщо встановлено); (3) ACPI thermal zone через WMI (`MSAcpi_ThermalZoneTemperature`, неточно, позначати «≈»). Якщо джерела немає, метрика ховається з підказкою, як її отримати. **Ніколи** не встановлювати WinRing0.

### 6.2. Кастомізація HUD
- Редактор розкладки: перетягування рядків, групи (FPS / GPU / CPU / RAM / Misc), вертикальна/горизонтальна/компактна-в-один-рядок орієнтація.
- Позиція: 9 якорів (кути, краї, центр) + зсув у px; окремо для кожного профілю гри; монітор.
- **Шрифти:** будь-який системний шрифт через DirectWrite, розмір, жирність, моноширинні цифри (`tabular-nums` / fallback Consolas), outline/тінь тексту для читабельності на будь-якому фоні.
- Кольори: текст, підписи, значення; **порогові кольори** для кожної метрики (наприклад FPS: < 60 червоний, 60–119 жовтий, ≥ 120 зелений; температура GPU: > 83 °C червоний).
- Фон панелі: колір, прозорість 0–100%, заокруглення, padding.
- Підписи: власний текст (`GPU`, `ГП`, emoji), одиниці (°C/°F, MB/GB), кількість знаків після коми.
- **Графіки:** frametime і FPS (окремо або разом), будь-яка інша метрика; тип: лінія / заповнена область / стовпці; ширина, висота, часове вікно (5–120 с), масштаб авто/фіксований, лінія цілі (наприклад 16.7 ms), підсвічування стрибків. Графік оновлюється 10–30 Гц (налаштовується), текст 1–4 Гц.
- **Пресети HUD:** *Minimal* (тільки FPS), *Competitive* (FPS + 1% low + frametime-графік), *Standard* (FPS, 1% low, GPU %/°C, CPU %/°C, RAM), *Detailed/Benchmark* (усе + графіки), *Streamer* (великий шрифт).
- Імпорт/експорт розкладок HUD як JSON / share-код.

### 6.3. Гарячі клавіші HUD (всі перепризначаються)
- Показати/сховати HUD (за замовчуванням `Ctrl+Shift+F10`, не конфліктує з популярними оверлеями: Alt+Z NVIDIA, Ctrl+Shift+O AMD, Win+G Xbox).
- Цикл пресетів HUD.
- Скинути статистику сесії (мін/макс/1% low).
- **Старт/стоп запису бенчмарку**: CSV з кожним кадром (timestamp, frametime, present mode) + 1 Гц сенсори; після стопу підсумок (avg, 1%, 0.1%, статери) у toast і в окремому файлі. Опційний авто-стоп через N секунд.
- Позначка (marker) у записі.
- Показати/сховати приціл, цикл прицілів (з розділу 5).

### 6.4. Вбудована діагностика «чи не шкодить оверлей»
- Telemetry helper відстежує Present mode гри **з увімкненим і вимкненим** оверлеєм (кнопка «Перевірити вплив», 2×5 секунд).
- Якщо з оверлеєм режим падає в `Composed: Flip`, показати пояснення та кроки: зменшити/прибрати HUD, перевірити, що MPO не вимкнений у системі, вимкнути «Desktop Capture» в NVIDIA overlay тощо. Додати опцію «Ховати HUD, поки йде гра, показувати по хоткею».

## 8. Якість, безпека, дистрибуція

- **Підпис коду** всіх exe (OV/EV або хоча б Azure Trusted Signing), стабільні імена файлів, `VERSIONINFO` з реальною назвою/виробником. Без пакувальників.
- Інсталятор (MSIX або WiX) + portable zip. Деінсталяція прибирає автозапуск і задачі.
- Оновлення: перевірка тільки при відкритті Settings або раз на добу, у фоні, **ніколи** під час активної гри; завантаження тільки після згоди.
- Мережа: за замовчуванням жодних запитів, окрім перевірки оновлень (можна вимкнути). Телеметрія/крешрепорти тільки opt-in.
- Логи: `%LOCALAPPDATA%\Sightline\logs`, ротація, рівні, без персональних даних.
- Збій будь-якого компонента телеметрії не валить Core (окремий процес + watchdog з backoff).

## 9. Тестування і приймання

1. **Unit-тести:** парсери конфігів і міграцій, генерація пресетів, парсери кодів Valorant/CS2, розрахунок 1%/0.1% low (на синтетичних рядах), seqlock IPC.
2. **Продуктивність:** скрипт з WPR/WPA або `typeperf` вимірює CPU/RAM Core у кожному стані з таблиці розділу 3 протягом 10 хв. Результати в `docs/perf-report.md`.
3. **Present mode:** матриця ігор (DX11, DX12, Vulkan, OpenGL; borderless) × (оверлей вимкнено / тільки приціл / приціл + HUD). Фіксувати режим через PresentMon CLI. Мета: приціл без HUD не змінює режим на залізі з MPO.
4. **Сумісність:** NVIDIA / AMD / Intel GPU; 1–3 монітори з різним DPI і частотою; HDR увімкнено/вимкнено (перевірити, що кольори прицілу коректні в HDR, використати scRGB/`DXGI_COLOR_SPACE` за потреби); Windows 10 22H2, Windows 11 23H2/24H2+.
5. **Робастність:** Alt+Tab ×50, зміна роздільної здатності гри, відключення монітора, перевстановлення драйвера GPU під час роботи, сон/гібернація, блокування екрана, гра від адміністратора.
6. **Античіт-перевірка (без ризику для акаунта):** перевіряти в тренувальних/офлайн-режимах; переконатися через Process Explorer/`listdlls`, що в процесі гри **немає** жодного модуля Sightline, а Sightline не тримає handle на гру з правами, ширшими за `QUERY_LIMITED_INFORMATION`. Додати цей чек-лист у `docs/anticheat-design.md`.
